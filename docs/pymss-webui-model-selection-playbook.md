# PYMSS WebUI 海量模型快速选型方案

## 目标

把模型目录从“文件列表”升级为“业务选型台”。面向音频分离业务，用户打开页面后应先按场景快速选到合适模型，再进入加载、分轨、预览、下载流程；高级用户仍可以按完整参数检索全部模型。

本方案适合后续多模型 WebUI 项目复用，尤其适合目录规模大、模型命名复杂、业务人员需要快速判断“该用哪个模型”的场景。

## 业务约束

- 主场景是音频分离，不是单独浏览模型目录。
- 输出口径固定为每个 stem 的 `48000Hz PCM_24 WAV`。
- “响应格式”对用户显示为：
  - `分轨`：实际走后端 JSON 接口，返回每个 stem 的 base64 WAV，前端可预览并单轨下载。
  - `zip`：后端打包所有选中 stem。
- 前端不向业务用户暴露 `json` 作为选项文案。
- 模型说明必须在模型目录、已加载模型区域、分离音频区域都能看到。

## 信息架构

默认入口采用“合并工作台”：

1. 左侧：模型选择控制台
2. 右侧：分离任务工作区

左侧承载场景筛选、搜索、选中模型摘要、下载、加载、批量下载；右侧承载当前加载模型说明、stem 选择、上传音频、响应格式、分轨预览和下载。

这种布局避免用户在“模型目录”和“分离音频”之间来回跳转。

## 双入口选型

### 场景选型

默认进入场景选型。场景固定为：

- 人声分离
- 伴奏分离
- 去混响
- 降噪/去人群声
- 对白/语音
- 4分轨
- 6分轨
- 53分轨
- 鼓组
- 单乐器
- 合唱/性别
- 声像空间
- 音频修复
- 呼吸/齿音

每个场景展示：

- 推荐模型
- 推荐原因
- 适合输入
- 输出轨道
- 模型大小/显存风险提示
- 本地是否已下载

推荐排序优先级：

1. 精华备注模型
2. 已下载模型
3. 高置信分类
4. target/config instruments 更贴合场景
5. 模型体积和显存风险更低

### 高级筛选

高级筛选保留完整 catalog 参数可查：

- 中文一级分类
- 中文二级分类
- 架构
- model_type
- target_stem
- config_instruments
- 模型大小
- 本地状态
- 分类置信度
- 关键词

排序方式：

- 推荐优先
- 已下载优先
- 大小升序
- 大小降序
- 名称排序

高级筛选必须能查看全部模型，包括低置信度、实验模型和非默认推荐模型。

## 增强模型索引

后端 Catalog API 负责实时状态，前端增强索引负责业务解释。

### 后端字段

后端继续提供：

- model id
- 是否 supported
- 本地是否 complete
- missing_count
- 下载源
- 文件状态
- 加载/下载/分离动作

不要求推理 API 改造。

### 前端增强索引字段

从完整 `model_catalog.json` 生成静态 TypeScript 数据，例如 `model-advisory-index.ts`。建议字段：

- `id`
- `primaryCategoryCn`
- `secondaryCategoryCn`
- `architecture`
- `modelType`
- `targetStem`
- `configInstruments`
- `classificationBasis`
- `confidence`
- `scenarios`
- `note.ability`
- `note.usage`
- `risk.size`
- `risk.memory`
- `manualNote`
- `recommendationWeight`

### 备注生成规则

优先级：

1. 人工“精华备注”
2. catalog 参数自动生成备注

自动备注拼接建议：

- 中文分类
- target_stem
- config_instruments
- classification_basis
- 架构
- 模型大小

示例：

```text
人声分离；输出目标：vocals。依据：config instruments 包含 vocals/instrumental。RoFormer 架构，适合高质量双轨分离。
```

### 53 分轨系列

`bs_mega_53stem_*` 系列统一归入 `53分轨` 场景。

生成备注时从具体 stem 名称提取乐器/对象，例如：

- piano：钢琴
- strings：弦乐
- guitar：吉他
- drums：鼓组

验收要求：53 个 `bs_mega_53stem_*` 全部进入 53 分轨场景。

## UI 呈现规则

### 模型行

每行显示：

- 模型名
- 推荐/精选标记
- 已下载标记
- 当前加载标记
- 业务分类
- 输出目标
- 模型大小
- 精华/自动备注

当前选中模型与批量下载选择必须分离：

- 左侧蓝点和行背景只表示“当前选中模型”
- 行尾复选框只表示“加入批量下载”

不要让蓝点复用批量下载状态，否则用户会误以为当前加载/下载目标已经切换。

### 选中模型摘要

模型列表上方放“当前选中模型”摘要：

- 模型名
- 精选/已下载/当前加载标记
- 业务分类
- 输出目标
- 模型大小
- 推荐说明
- `加载选中模型`
- `下载模型`

下载按钮始终对当前选中模型生效。

### 已加载模型区域

显示：

- 当前加载模型名
- 能力说明
- 输出目标
- 使用备注
- sample rate

不要只显示模型文件名。

### 分离结果区域

`分轨` 模式下：

- 每个 stem 一行
- 可直接播放预览
- 可单独下载 `.wav`

`zip` 模式下：

- 显示打包下载按钮

## 视觉规范

适合工具型 WebUI 的视觉方向：

- 字号比原始页面略大，但不要做成营销页大标题。
- 面板边界要清楚，建议使用明确的边框和浅底色区分区域。
- 左右两栏比例大致为模型控制台 40%，分离工作区 60%。
- 卡片和行列表要有清楚分隔线。
- 选中态建议使用明显浅蓝背景加左侧蓝色指示线/蓝点。
- 不嵌套卡片；工作区用分段面板和表格化列表。

推荐主色：

- 顶部/侧栏深蓝：`#183756`
- 工作区浅蓝分段：`#eef5fc`
- 页面底色：`#f6f9fc`
- 选中背景：`#e7f0ff`
- 选中蓝：`#2563eb`

## 下载可靠性

WebUI 下载按钮调用后端下载接口，不应在前端绕过。

如果下载失败，优先检查：

- 目标模型是否为当前选中模型
- UI 是否把批量选择误当成当前模型选择
- 后端下载源是否可用
- sidecar 配置文件大小/哈希是否与远端实际文件不一致

下载器建议：

- 权重文件继续严格校验大小/哈希。
- `.yaml`、`.yml`、`.json` 这类小型配置文件允许远端轻微变化，只要下载成功即可保留。

这样可以避免权重已经下载成功，但配置文件因跨源索引大小差异导致模型仍显示未完成。

## 实施步骤

1. 导入完整 `model_catalog.json`。
2. 编写生成脚本，输出增强模型索引。
3. 合并人工精华备注覆盖层。
4. 实现场景匹配和推荐排序。
5. 实现高级筛选和组合排序。
6. 将 Catalog API 实时状态与增强索引按 model id 合并。
7. 将模型说明接入模型目录、已加载页、分离页。
8. 将默认入口改为合并工作台。
9. 修复选中态与批量下载状态分离。
10. 验证下载、加载、分离、预览、单轨下载。

## 验收清单

数据完整性：

- 增强索引模型数等于 catalog 模型数。
- 每个 catalog model 都能匹配到 advisory metadata。
- 53 个 `bs_mega_53stem_*` 全部归入 53分轨。

UI 功能：

- 场景切换后模型列表正确变化。
- 高级筛选组合条件正确生效。
- 搜索可命中模型名、中文分类、备注、stem、config instruments。
- 已下载/未下载状态来自实时 API。
- 下载、批量下载、加载、详情不回归。
- 当前选中模型蓝点和行背景同步。
- 批量下载复选框不影响当前选中模型。
- 响应格式显示 `分轨` 和 `zip`，不显示 `json`。
- 分轨输出可逐 stem 预览和下载 `.wav`。

业务场景：

- “我要提取干净人声”优先看到人声 SOTA/已下载模型。
- “我要去混响对白”能看到去混响模型并显示 SDR/备注。
- “我要做 4 分轨但怕显存”能区分 XL 和 huge_scnet。
- “我要单独提钢琴/弦乐”能进入 53分轨并找到对应 stem。
- “我要 speech/music/effects 三轨”能找到 DNR 模型。

部署验证：

- `/health` 返回 ok。
- 容器状态 healthy。
- Catalog API 返回模型总数符合预期。
- 缺失模型下载后 local.complete 变为 true。
- 真实音频分离 smoke test 通过。
- WAV header 验证为 48000Hz、24-bit PCM。

## 后续项目复用建议

复用时不要直接复制某个页面样式，优先复制方法：

- 先定义业务场景，不从模型架构出发。
- 建立“后端实时状态 + 前端业务索引”的合并模型。
- 人工精选备注做覆盖层，不手写全部模型。
- 默认给业务人员场景入口，给工程人员高级筛选入口。
- 当前选中、批量选择、当前加载三种状态必须独立。
- 输出格式和用户文案必须与真实交付物一致。

建议文件结构：

```text
src/lib/model-advisory-index.ts
src/lib/model-selection.ts
src/lib/components/WorkbenchView.svelte
scripts/generate-model-advisory-index.mjs
scripts/check-model-advisory-index.mjs
docs/model-selection-playbook.md
```

最小迁移判断：

- 模型数量超过 50 个，需要场景选型。
- 模型名不能直接表达业务用途，需要增强索引。
- 用户需要在同一页面完成选型、加载、执行，需要合并工作台。
- 输出结果需要预览，需要按业务结果而不是原始接口字段设计 UI。
